How a neural networkactually learns

Activation functions, hidden layers, gradient descent — the procedure that turns "find good values of W and b" from a slogan into an algorithm.

PERCEPTRON → MLP FORWARD + BACKPROP GRADIENT DESCENT
WHERE WE ARE

Session 1 (ANN intro) covered the perceptron: one neuron, weights and a bias, a linear output ŷ = Σwᵢxᵢ + b. We knew the equation but had no idea where the weights came from.

Today fills that gap. We add the missing pieces — activation functions, hidden layers, a loss function, and the algorithm that actually adjusts the weights (gradient descent). By the end, the lecturer's claim that "training a model means finding good values of W and b" stops being a slogan and starts being a procedure you could write yourself.

Next session (Session 3, coding): end-to-end TensorFlow — pick a dataset, declare a network, fit, predict.

A neural network learns by guessing weights, scoring how wrong it is, and using calculus to nudge each weight in the direction that reduces error — repeated thousands of times. Everything else — activation functions, hidden layers, learning rates, dropout — is machinery wrapped around that one loop.
§ 01 — STARTING POINT

Quick recap (60 seconds)

  • AI ⊃ ML ⊃ DL ⊃ Generative AI ⊃ LLMs. Each is a strict subset of the next.
  • Supervised problems give the model both X (inputs) and Y (correct answer). The model's job is to learn the pattern linking X to Y. Once locked in, new X → predicted Y.
  • Supervised splits by the type of Y: regression (Y is a number) vs classification (Y is a class).
  • Perceptron = a single neuron. Takes inputs x₁, x₂, …, xₙ, multiplies each by a learned weight, adds a learned bias: ŷ = Σᵢ wᵢxᵢ + b. That equation can only produce a number. So as it stands, a perceptron is a regressor only.
§ 02 — NON-LINEARITY

Why we need activation functions

The perceptron equation ŷ = Σwᵢxᵢ + b is a linear function of its inputs. It can only ever produce a number, and that number can be any real value. Two problems with that:

  1. Classification needs a class, not a number. If the answer is "spam / not spam," a raw number like 2003.4 is not useful.
  2. Stacking linear functions gains nothing. Algebraically, A·(B·x + c) + d = (AB)·x + (Ac + d) — one linear transform with different constants. Without a non-linearity between layers, a 100-layer network is mathematically identical to a single layer.

The fix is to wrap the linear output in a non-linear function called the activation function:

z = Σ wᵢxᵢ + b ← linear part
ŷ = φ(z) ← φ adds the non-linearity

The activation function φ is chosen, not learned — you pick it as part of designing the network.

The activation menu

Correction — the step function isn't "outdated," it's untrainable.

The lecturer called the step function "old" and moved on. The real reason no modern network uses it: its derivative is zero almost everywhere (and undefined at z=0). Gradient descent — the algorithm we're about to learn — works by following the derivative. A function whose derivative is zero everywhere gives gradient descent no signal: every weight update is multiplied by 0, no learning happens. ReLU has the same problem at exactly z=0, but the slope is 1 everywhere on the positive side, so signal flows freely.

Correction — sigmoid output is strictly between 0 and 1, never equal to them.

The lecturer said "you may get 0 or 1." Mathematically, 1/(1+e⁻ᶻ) approaches 0 as z → −∞ and approaches 1 as z → +∞ but never reaches either. Open interval (0, 1). The lecturer also flagged that the sigmoid plot in her slide was drawn wrong with negative values — she's right; sigmoid is always positive.

Correction — "ReLU is for regression, sigmoid is for classification" mixes up two different roles.

ReLU is a hidden-layer activation; it introduces non-linearity inside the network regardless of what task you're solving. The activation on the output layer is what's task-specific. A standard image-classifier uses ReLU in every hidden layer and softmax on the output. The clean mental model:

LayerRegressionBinary class.Multi-class
HiddenReLUReLUReLU
Outputnone (identity)sigmoidsoftmax
Correction — multi-class is softmax, not "bucketed sigmoid."

The lecturer suggested slicing sigmoid's (0,1) output into thresholds — 0–0.3 → class A, 0.3–0.6 → class B, 0.6–1.0 → class C — as a multi-class scheme. This is not how anyone does it. The standard approach is a softmax output layer with one neuron per class: each neuron outputs the probability that the input belongs to that class, and the probabilities sum to 1. Take argmax (the index of the largest) to pick the predicted class. Bucketed sigmoid is not used in practice.

Why ReLU dominates modern networks

ReLU is dead simple — max(0, z) — and that's its strength.

  • Cheap to compute. No exponentials, no division. Modern networks compute ReLU billions of times per training step; cheap arithmetic compounds.
  • No vanishing gradient on the positive side. Sigmoid and tanh saturate — for large |z|, their derivatives are essentially zero, which kills gradient flow through deep stacks (see §09). ReLU's derivative on the positive side is exactly 1, so gradients pass through unattenuated.
  • Sparsity. Roughly half the neurons in a ReLU layer output 0 on any given input. Sparse activations are easier to interpret and faster to compute downstream.

The trade-off: ReLU outputs 0 for all negative inputs. If a neuron's weights drift to a region where its input is always negative, that neuron is permanently dead — outputs 0 forever, gradient is 0, never recovers. Leaky ReLU and PReLU keep a tiny slope on the negative side specifically to avoid that.

§ 03 — REPRESENTATION

Hidden layers: where the actual learning lives

A perceptron has only two layers: input and output. Every input column connects directly to the output, and every column carries equal weight in the calculation. That's a problem.

Real datasets are mostly noise

The lecturer used a house-price example with three input columns:

  • square_feet — strongly predictive (bigger house → higher price)
  • city_distance — strongly predictive, inversely (further from city → lower price)
  • number_of_doors — basically noise (a 50-door house isn't worth 16× a 3-door house)

A perceptron has no way to structurally down-weight number_of_doors. It just multiplies it by some learned weight and adds it in. If that column is genuinely noise, the best it can do is learn a weight near zero — but it can't ignore the column.

What hidden layers buy you

A hidden layer is one or more rows of neurons sitting between input and output. Each hidden neuron is a tiny perceptron: it sees all the inputs from the previous layer, computes its own weighted sum, applies its own activation, and passes the result forward. Every input connects to every hidden neuron (that's why it's called fully connected or dense). Every hidden neuron connects to every output neuron.

What this actually does: each hidden neuron learns to combine the raw inputs into a more useful intermediate feature. One neuron might end up combining square_feet and city_distance into a "value-per-km" signal; another might do something we'd never think of. The output layer then reads these learned features instead of the raw inputs.

This is called representation learning — the network discovers its own internal vocabulary for describing the data, and that vocabulary is what makes deep networks powerful. It's also what the Universal Approximation Theorem (Cybenko 1989) is about: a sufficiently wide single-hidden-layer network can approximate any continuous function. Hidden layers aren't a nice-to-have; they're what separates a neural network from linear regression.

Correction — hidden layers help with much more than feature selection.

The lecturer framed hidden layers as enabling "feature selection via dropout." That's a partial truth. Hidden layers are essential even without dropout — they provide the non-linearity that lets the network model complex relationships (as the activation-function section above explained, stacking linear layers without non-linearity collapses to a single linear layer). Dropout is a separate technique, layered on top.

How big? How deep?

There's no formula. Two practical rules of thumb:

  1. Hidden-layer size in the same ballpark as the input. If you have 3 input columns, 4–5 hidden neurons is a reasonable start. With 50 columns, try 50–60 in the hidden layer. Don't go from 50 columns to a 3-neuron hidden layer — that's a brutal bottleneck.
  2. Start with one hidden layer. Add a second only if performance plateaus. Each additional layer multiplies the parameter count (and training time, and memory) — there is no free depth.

The cost-vs-accuracy trade-off is real:

  • More layers / more neurons → more parameters → more training time, more memory, more compute cost.
  • More parameters → more capacity to fit training data, but also more capacity to overfit (memorise training, fail on new data).
  • The "best" architecture for your problem is found empirically. There is no analytical answer.

Counting parameters

Number of parameters = number of connections (one weight each) + number of non-input neurons (one bias each).

Quick check from the lecturer's example: 3 inputs → 4 hidden → 1 output is 3×4 + 4×1 = 16 weights, plus 4 + 1 = 5 biases. Total 21 parameters. The lecturer's "16 links → 32 parameters" framing counted each link as having both a weight and a bias, which is the older textbook convention — modern frameworks (TensorFlow, PyTorch) attach one bias per neuron, not one per link. Either way you arrive at the same model, just labelled differently.

Now scale this up. When you read that GPT-3 has 175 billion parameters or Llama 3 405B has 405 billion — those are weights and biases just like these. Same machinery; many more of them.

JAVA/SPRING BRIDGE

Weights are the cream of the model. If you have the trained W and b for a network, you have the model — you can load them and predict from any input. Same as having the compiled .jar plus its serialised state: you can rehydrate the running app from those two things. This is also why companies guard model weights so carefully (and why Meta's release of Llama weights was a big deal — they shipped the .jar).

Dropout, properly

Dropout is a regularisation technique introduced by Srivastava et al. (2014). During training, at each step, you randomly delete (set output to 0) a fraction p of neurons in a layer — say 20% or 30%. The remaining neurons take up the slack. Next step, a different random 20% are dropped.

The point is not that the network "learns which links matter." The point is to prevent co-adaptation: when you train without dropout, neurons can become dependent on the exact presence of other specific neurons (one neuron only works if its three buddies are also active). That over-coupling makes the network brittle on new data. By randomly dropping neurons, you force each one to learn something useful on its own.

Correction — dropout's job is regularisation, not feature selection.

The lecturer's framing ("the network eventually figures out the right architecture") is a useful intuition but it isn't the textbook explanation. Read it as: dropout makes the network more robust by training many slightly different sub-networks and averaging their behaviour. Mathematically it approximates training an ensemble — at test time, the full network with no dropout behaves like the average of those sub-networks.

JAVA/SPRING BRIDGE

Dropout ≈ Chaos Monkey for neurons. Netflix's Chaos Monkey kills random production instances to force engineers to build resilient services. Dropout kills random neurons to force the network to build resilient representations. Same idea, smaller scale.

§ 04 — THE LOOP

The training loop

We have the architecture. We need the algorithm that finds good W and b. The training loop has three movements: forward pass → measure error → update weights, repeated for the whole dataset, repeated again, and again, for many epochs.

Step 1 — forward pass (feedforward)

For one row of training data (one example):

Input vector x = (x₁, x₂, ..., xₙ)
   ↓ apply layer 1: z₁ = W₁x + b₁; a₁ = φ(z₁)
   ↓ apply layer 2: z₂ = W₂a₁ + b₂; a₂ = φ(z₂)
   ↓ ...
   ↓ apply output layer: ŷ = φ(W_L · a_{L-1} + b_L)

This is just matrix multiplication and elementwise activation — fast on a GPU because GPUs are built for matrix math. The output ŷ is the network's current best guess for this example, given the current W and b. On the very first pass, W and b are random; ŷ will be garbage.

Step 2 — measure the error

Compare ŷ (what the network said) against y (the truth, given by the supervised dataset). The function that quantifies the gap is the loss function. For regression problems the canonical choice is squared error:

lossi = (ŷi − yi)²

The square does two useful things: (1) it makes positive and negative errors both count (so 5-too-high and 5-too-low don't cancel), and (2) it grows faster than linearly, so big mistakes get punished harder than small ones.

The loss is computed per example. The cost is the average loss across all examples in the dataset (or batch — see §07):

cost J(W, b) = (1/N) · Σi (ŷi − yi)²
SIDE NOTE — THE 1/2 VS 1/N CONFUSION

The transcript had a moment where the cost was first written as (1/2) · Σ(ŷ−y)², then corrected to (1/N) · Σ(ŷ−y)². Both forms appear in textbooks. The 1/N form gives the true average (mean squared error, MSE) — this is what tf.keras.losses.MeanSquaredError returns. Some textbooks write (1/2N) · Σ(...)² instead — the extra 1/2 has no effect on optimisation (the gradient just scales by ½, which the learning rate absorbs) but cleans up the derivative algebra (the chain rule's factor of 2 cancels the 1/2). They're the same optimisation problem; use whichever your framework uses.

Step 3 — update the weights

This is the part that wasn't possible to explain in Session 1. Now we have the machinery. The cost J(W, b) is a function of every weight and bias in the network. We want to find the W and b that minimise J. The algorithm that does this is gradient descent. The next two sections build it from scratch.

§ 05 — DOWNHILL

Gradient descent

The intuition (one parameter at a time)

Imagine the cost function for a single weight w. Plot it: x-axis is w, y-axis is the cost J(w). For squared-error loss with a linear model, this curve is a parabola — bowl-shaped with one minimum.

You don't know where the minimum w* is. You start at some random w and want to walk downhill. Two questions:

  1. Which direction? Left or right?
  2. How big a step?

Gradient descent answers (1). The gradient is the slope of the curve at your current location. If the slope is positive (curve going up to the right), the minimum is to your left, so you decrease w. If the slope is negative, the minimum is to your right, so you increase w. In both cases, the rule is "step opposite the gradient" — hence the name descent.

The learning rate answers (2). The gradient tells you direction. The learning rate η (sometimes α or lr) is a number you choose that controls how big a step to take in that direction. Combined:

w_new = w_old − η · (gradient of cost at w_old)

What the learning rate actually controls

This is worth dwelling on, because it's the single most-tuned hyperparameter in deep learning.

Learning rateWhat happens
Too smallTraining works but is glacially slow. You take baby steps toward the minimum. Real-world cost: weeks of GPU time instead of hours.
Too bigYou overshoot the minimum on every step. The cost can increase over training — the network bounces around in the bowl. In the worst case the cost diverges to infinity ("blowing up").
Just rightBig steps when far from the minimum (high cost), small steps as you approach (low cost).

In practice you don't pick a single learning rate by hand — you use a scheduler (start high, decay over time) or an adaptive optimiser (Adam, RMSProp — they adjust the step per parameter based on recent gradients).

Local minima and saddle points

The parabola picture is the friendly case. The real cost surface of a deep network is high-dimensional (millions of parameters) and lumpy. You might descend into a local minimum that isn't the global one. Or land on a saddle point where the gradient is zero but you're not at a true minimum.

In practice deep networks rarely get stuck in bad local minima — the high dimensionality means most "minima" are actually saddles you can escape from, and the local minima you do find tend to give similar test performance. This is more reassuring empirically than it sounds in theory.

Correction — "train until error = 0" isn't the right stopping rule.

The lecturer described training as repeating epochs until the cost reaches 0. In practice, reaching exactly 0 means you've memorised the training data (overfit), and the model will perform terribly on new data. Real stopping rules: (a) the validation loss stops decreasing for N epochs (early stopping), (b) the gradient magnitude drops below a threshold, or (c) you hit a fixed epoch budget. Aim for the cost to plateau, not to vanish.

§ 06 — THE CALCULUS

Deriving the update rule

This section is optional if you trust the formula and want to skip to coding. It's worth following once so you've seen the derivation, then you can forget it (TensorFlow and PyTorch handle this for you via autograd).

Setup

Take the simplest possible model — a one-input, one-output linear model with no activation:

ŷ = w·x + b

Cost (squared error, one example for clarity — the average drops out cleanly):

J(w, b) = (ŷ − y)² = (w·x + b − y)²

Define error = ŷ − y. Then J = error².

Derive ∂J/∂w using the chain rule

The chain rule: if J = f(g(w)), then dJ/dw = f'(g) · g'(w). Here f(u) = u² and g(w) = error = w·x + b − y:

∂J/∂w = 2 · error · ∂(error)/∂w
= 2 · error · ∂(w·x + b − y)/∂w
= 2 · error · x ← ∂(wx)/∂w = x; b and y don't depend on w

Derive ∂J/∂b the same way

∂J/∂b = 2 · error · ∂(error)/∂b
= 2 · error · ∂(w·x + b − y)/∂b
= 2 · error · 1 = 2 · error

The update rules

Plug these into param_new = param_old − η · gradient. The factor of 2 just gets absorbed into the learning rate (it's a constant):

w_new = w_old − η · error · x
b_new = b_old − η · error

That matches what the handout has:

Correction — these update rules are for a single linear neuron, not a multi-layer network.

What we just derived works for a perceptron (no activation, one neuron). For a multi-layer network with activation functions, the same idea applies but the chain rule has more links — the gradient has to flow backwards through every layer's activation derivative. That fuller algorithm is called backpropagation (Rumelhart, Hinton, Williams, 1986). The intuition is identical; the bookkeeping is more elaborate. TensorFlow and PyTorch do it for you.

After applying the update to every example in the dataset, you've completed one epoch. Then you do it again, and again. Typically networks train for tens to hundreds of epochs.

§ 07 — BOOKKEEPING

Epoch, batch, iteration

These three terms get mixed up constantly. The handout has the cleanest definition; here it is.

  • Epoch — one complete pass through the entire training dataset.
  • Batch size — how many training examples you process before updating the weights once.
  • Iteration — one weight update. Equivalently, one batch processed.
WORKED EXAMPLE

You have 2,000 training examples. You set batch size = 500. Then one epoch = 4 iterations, because the dataset divides into 4 batches of 500. If you train for 10 epochs, you've done 40 iterations = 40 weight updates total.

This decomposition gives three flavours of gradient descent:

VariantBatch sizeUpdatesTrade-off
Batch GD (full-batch)Entire datasetOnce per epochMost stable; slowest; can't fit large datasets in memory
Stochastic GD1 exampleOnce per exampleFastest updates; very noisy; never settles cleanly
Mini-batch GDTypically 32–512Once per batchThe modern default — balances stability and speed; matches GPU memory layout

When TensorFlow/PyTorch documentation says "SGD," they almost always mean mini-batch GD with a batch size > 1 — the name has drifted to cover all stochastic variants.

NOTE ON THE LECTURER'S EPOCH DESCRIPTION

The transcript describes "one epoch" as guessing W and b, predicting for all rows, computing the cost, then doing one update with backprop. That matches batch GD specifically. In mini-batch GD (what your TensorFlow code will run tomorrow), you update multiple times within a single epoch — once per batch. Same idea, finer-grained.

§ 08 — INERTIA

Momentum (preview)

The handout introduces momentum-based gradient descent but the transcript only mentioned it briefly. Worth a paragraph so you recognise it tomorrow when TensorFlow's optimiser list has SGD(momentum=0.9) and Adam.

Vanilla gradient descent uses only the current gradient to decide which way to step. Momentum-based gradient descent keeps a moving average of recent gradients and uses that instead:

v_t = γ · v_{t-1} + η · ∇w_t ← v is the "velocity"; γ ∈ (0, 1), typically 0.9
w_{t+1} = w_t − v_t

The γ · v_{t-1} term is the history. If you've been moving consistently in one direction, momentum keeps you moving that way — the velocity builds. If the gradient suddenly flips, momentum smooths the change rather than jerking instantly.

Why it helps: in long shallow valleys (very common in loss landscapes), vanilla GD oscillates back and forth across the valley walls while creeping slowly forward. Momentum dampens the oscillation and accelerates the forward motion. Empirically it converges 2–10× faster than vanilla GD on typical problems.

The downside: momentum can overshoot the minimum the same way a rolling ball overshoots the bottom of a valley. You see a few u-turns at the end of training, but it still converges faster than vanilla GD.

Adam (Kingma & Ba, 2014) extends this: it tracks a moving average of gradients (momentum) and a moving average of squared gradients (adaptive per-parameter learning rate). Adam is the default optimiser in most modern deep learning code.

§ 09 — THE 50-YEAR DELAY

Vanishing gradient: why deep learning took 50 years

The lecturer mentioned that the perceptron was introduced by Rosenblatt in 1957, and that nothing much happened in deep learning until around 2010. The single-most-cited reason for the 50-year delay is the vanishing gradient problem.

What it is

Gradient descent works by computing ∂J/∂w for every weight and propagating that signal backwards through the network. In a deep network, that signal goes through many layers — and at each layer, it gets multiplied by the layer's activation derivative.

Sigmoid and tanh both have derivatives at most 0.25 (sigmoid) or 1 (tanh) — but for most input values, both derivatives are very close to 0 because the curves saturate at their asymptotes. When you multiply 10 small numbers together, you get a very small number. By the time the gradient signal reaches the early layers of a deep network, it's effectively zero — those layers stop learning. This is vanishing gradient.

What actually unblocked deep learning

The "ReLU solved it" framing in the transcript is partially right, but the deep-learning revival circa 2006–2012 had three legs, not one:

  1. ReLU (Glorot, Bordes, Bengio, 2011). Derivative is exactly 1 on the positive side — gradients pass through unattenuated. This is the activation-function piece.
  2. Better weight initialisation (Glorot/Xavier init 2010, He init 2015). Random weights drawn from a distribution scaled to keep activation variances roughly constant across layers — prevents the signal from blowing up or dying as it propagates forward.
  3. GPUs + big data (ImageNet 2012, AlexNet). Without GPUs to do the matrix math fast, even with the algorithmic fixes you couldn't train large networks in reasonable time.

You also have batch normalisation (Ioffe & Szegedy 2015), residual/skip connections (ResNet, He et al. 2015), and the Adam optimiser (Kingma & Ba 2014) as further unlocks. Modern deep learning is the combination of these fixes — no single one of them by itself.

§ 10 — BRIDGE

From here to LLMs

The Q&A near the end of the session was about whether a generic LLM "knows" a specific bank's data. This is worth answering crisply because it connects everything we've done.

A modern LLM (GPT-4, Claude, Llama, Gemini) is a giant neural network — decoder-only transformer, hundreds of billions of parameters — trained on hundreds of billions of words from the public internet, books, code, etc. The training procedure is the same loop we just covered: forward pass, compute loss, backpropagate, update weights. Repeat for trillions of training tokens.

What you get out the other end is a .bin file (or several) full of weights and biases — exactly the same kind of W and b we've been talking about. Just a lot more of them.

Why an off-the-shelf LLM is bad at your domain

The model has been trained on generic data. It doesn't know that in your bank, FICO scores below 580 are flagged for manual review, or that your customer schema renames created_at to originated_on. When asked, it will confabulate — produce plausible-sounding answers that don't reflect your actual data. This is called hallucination; it's not a bug, it's the default behaviour of a probabilistic text generator that has no ground-truth check.

Fine-tuning is "retraining, partially"

To give the model your domain knowledge, you can fine-tune it: take the pre-trained W and b, then continue the same training loop on a smaller dataset of your domain examples. The weights shift to accommodate your data without throwing away the general knowledge. This is what JPMorgan's FinBot, Bloomberg's BloombergGPT, and similar domain LLMs are.

REMEMBER THIS

Fine-tuning is exactly the loop from this session, run again on different data. Forward pass, loss, backprop, update. That's why we spent 155 minutes on the perceptron — because the same algorithm scales to 175 billion parameters.

Retrieval-augmented generation (RAG) is a different and often cheaper approach: don't retrain the model, just fetch the relevant company-specific documents at query time and stuff them into the prompt. We'll cover this in a future session.

Verify — "10 lakh open-source LLMs on Hugging Face."

Hugging Face passed 1 million model uploads in mid-2024 and the count has grown since; by May 2026 it's closer to 2 million+. Note that the catalogue counts any uploaded model — most are fine-tunes or small derivatives of a handful of base models (Llama, Mistral, Qwen, …). The number of genuinely distinct base models is in the dozens.

§ 12 — TL;DR

Interview cheat-sheet

If somebody asks you in an interview "how does a neural network learn?" here's the 30-second answer:

"It guesses initial weights, runs a forward pass to predict, computes a loss against the truth, computes the gradient of the loss with respect to every weight using the chain rule (this is called backpropagation), and updates each weight by stepping opposite the gradient with a small learning rate. Repeat for many epochs until the loss stops decreasing."

If they push further, you can name:

  • MSE for regression, cross-entropy for classification (we'll meet cross-entropy in a later session)
  • ReLU for hidden layers, softmax for multi-class output
  • Adam as the default optimiser (improvement on vanilla SGD)
  • Dropout and batch norm as standard regularisers
  • Mini-batch as the default GD variant (not full-batch, not pure stochastic)
  • Vanishing gradient as the historical problem that ReLU + better init solved

Glossary

Activation function
A non-linear function applied to a neuron's linear output. Without it, stacking layers gains nothing. Common: ReLU (hidden), sigmoid (binary output), softmax (multi-class output), tanh (older hidden), step (historical).
Backpropagation
The algorithm that propagates the loss gradient backwards through the network's layers using the chain rule, so every weight can be updated. The multi-layer generalisation of the derivative we worked out in §06.
Batch / batch size
A chunk of training examples processed together before one weight update. Mini-batch size (32–512) is the modern default.
Bias (b)
A learned constant added to a neuron's linear combination of inputs. Lets the activation shift independently of the input.
Cost function
Average of the loss over a dataset (or batch). Gradient descent minimises it.
Dropout
Randomly zeroing the output of a fraction of neurons during training. Regulariser that prevents co-adaptation. Default rate 0.2–0.5.
Epoch
One complete pass through the entire training dataset.
Feedforward (forward pass)
Computing the network's prediction by applying layers from input to output.
Fully connected (dense) layer
A layer where every neuron is connected to every neuron in the previous layer.
Gradient
The vector of partial derivatives of the cost with respect to every weight. The "direction of steepest increase." Gradient descent steps opposite the gradient.
Gradient descent
The optimisation algorithm: param_new = param_old − η · gradient. From operations research / optimisation; deep learning uses it.
Hidden layer
Any neuron layer that isn't the input or output. Where representation learning happens.
Hyperparameter
A setting of the training process that you choose, not the network learns. Learning rate, batch size, number of layers, dropout rate, optimiser, etc.
Iteration
One weight update. Equivalently, one batch of training data processed.
Learning rate (η, α, lr)
The step-size multiplier in gradient descent. Single most-tuned hyperparameter.
Loss function
The per-example error measure. Sum (or average) over examples gives the cost.
Mini-batch gradient descent
Gradient descent that updates after each mini-batch (typically 32–512 examples). Modern default.
Momentum
A modification of GD that keeps a moving average of recent gradients — trajectory has "inertia." Helps in long shallow valleys.
MSE (mean squared error)
(1/N)·Σ(ŷ−y)². The standard regression loss.
Optimiser
The algorithm that uses the gradient to update weights. SGD, SGD with momentum, Adam, RMSProp, AdaGrad.
Overfitting
When a network learns the training data so well it stops generalising. Symptoms: training cost drops, validation cost rises. Cures: more data, regularisation, early stopping.
Parameter
A weight or bias. What the network learns. Contrast with hyperparameters (chosen).
Perceptron
A single neuron with weights, bias, and (in modern usage) an activation. Rosenblatt, 1957.
ReLU (Rectified Linear Unit)
max(0, z). Default hidden-layer activation in modern networks.
Sigmoid
1/(1+e⁻ᶻ). Outputs in (0, 1). Used on the output layer of binary classifiers.
Softmax
Generalises sigmoid to multi-class: produces a probability distribution over K classes. Used on the output layer of multi-class classifiers.
Step / Heaviside function
1 if z ≥ 0 else 0. Historical; not used in modern networks — derivative is 0 almost everywhere.
Stochastic gradient descent (SGD)
Strictly: GD that updates after each single example. In practice the term is used loosely to mean mini-batch GD.
Tanh
Hyperbolic tangent, outputs in (−1, 1). Used as a hidden activation in older networks (RNNs).
Universal Approximation Theorem (UAT)
Cybenko 1989. A sufficiently wide single-hidden-layer network can approximate any continuous function. Explains why hidden layers are essential.
Vanishing gradient
In deep networks with saturating activations, the gradient becomes vanishingly small as it propagates backwards. Early layers stop learning. Solved by ReLU + better init + skip connections.
Weight (w)
A learned coefficient multiplying one input to a neuron. With bias and activation, defines what the neuron computes.
