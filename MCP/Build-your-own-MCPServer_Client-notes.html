Build your own MCP server and client.

FastMCP, three decorators, thirty lines of Python. The producer side of MCP.

FASTMCP · NOT FASTAPI @mcp.tool / @mcp.resource / @mcp.prompt STDIO + HTTP TRANSPORTS
WHERE WE ARE

Lecture 1 covered the consumer side of MCP — using third-party servers in Cursor. Today we flip the producer/consumer relationship. We write our own server in Python using FastMCP, then write a client that connects to it, lists what it exposes, and calls each capability. The result is a single working example you can copy and adapt for any real-world tool you want to expose to an LLM.

The two Python files in this folder (simple_server.py, simple_client.py) are the working code. By the end of this session you'll know what each line does and why.

Writing an MCP server is roughly thirty lines of Python. You import FastMCP, instantiate a server, decorate your functions with @mcp.tool (or @mcp.resource, @mcp.prompt), and run it. A client connects with one line, lists what's available with one method, and calls anything with one more.
§ 01 — MOTIVATION

Why write your own server?

Lecture 1 ended with a question from the cohort: "if I have third-party MCP servers for everything, why would I write my own?" The answer is three-fold.

  1. Domain-specific logic. Your business has rules and computations no third party knows about. The lecturer's real example: a healthcare org with 3,000+ SQL functions that detect fraud patterns specific to their data. No third-party MCP server exists for "compute the per-member-per-month cost anomaly score using our internal claims schema." You write it.
  2. Security and isolation. Third-party servers run code you didn't audit and may make outbound network calls you didn't authorise. In regulated industries (healthcare, finance), most third-party MCPs are blocked outright; the only way to expose tools to your agent is to write them yourself behind your firewall.
  3. Standardisation across teams. If 5 teams in your org each need a "query our data warehouse" tool, you write one MCP server and host it; everyone consumes it. The alternative — five copies of the same SQL-and-tokenisation code — is exactly the duplication problem MCP exists to solve.

So: write your own server when the logic is domain-specific, the data is sensitive, or you want to share tools across teams. Use third-party servers for commodity capabilities (GitHub, web search, browsers, public APIs).

§ 02 — FRAMEWORK

FastMCP: the Python framework

You don't write MCP servers against the raw protocol. You use FastMCP — a high-level Python framework that hides the JSON-RPC plumbing behind decorators.

pip install fastmcp

FastMCP started as a community project by Jeremiah Lowin (jlowin/fastmcp) and is now the official Python MCP framework. The Anthropic Python SDK's mcp.server.fastmcp is essentially the same code path.

Correction — FastMCP is not FastAPI.

The lecturer's transcript says "FastAPI" several times. They're different:

  • FastAPI — a Python web framework for HTTP REST APIs (Sebastián Ramírez, 2018). Unrelated to MCP.
  • FastMCP — the Python MCP framework. The thing the example uses.

The simple_server.py and simple_client.py files in this folder both import fastmcp, not fastapi.

§ 03 — SERVER

Anatomy of an MCP server

Here is the complete contents of simple_server.py from this folder, annotated:

"""
Beginner MCP Server - Tool, Resource, and Prompt
"""
import json

from fastmcp import FastMCP                          # ← FastMCP, not FastAPI

mcp = FastMCP(name="Beginner MCP Server")            # ← instantiate the server


# ---- 1. TOOL: Function the LLM can call ----
@mcp.tool                                            # ← @mcp.tool, not @tool
def add(a: int, b: int) -> int:
    """Add two numbers together."""                  # ← docstring = LLM-visible description
    return a + b


@mcp.tool
def greet(name: str) -> str:
    """Say hello to someone."""
    return f"Hello, {name}!"


# ---- 2. RESOURCE: Read-only data ----
@mcp.resource("resource://greeting")                 # ← URI is required
def get_greeting() -> str:
    """A simple greeting message."""
    return "Hey! Welcome to MCP"


@mcp.resource("resource://config")
def get_config() -> str:
    """Server configuration info (JSON string for all transports)."""
    return json.dumps({                              # ← return STRING, not dict
        "version": "1.0",
        "name": "Beginner MCP",
        "author": "MCP Demo",
    })


# ---- 3. PROMPT: Reusable template for LLMs ----
@mcp.prompt
def explain_topic(topic: str) -> str:
    """Generate a request to explain a topic in simple terms."""
    return f"Can you explain '{topic}' in a beginner-friendly way? Use simple words and include one example."


if __name__ == "__main__":
    import sys
    if "--http" in sys.argv:
        mcp.run(transport="http", host="127.0.0.1", port=8001)
    else:
        mcp.run()                                    # stdio is the default

Important — the get_config return type was a bug in the original code.

The lecturer's live demo hit Error reading resource: content must be string, bytes, list. Got dictionary. That's because an earlier version of get_config() returned a Python dict directly. MCP resources must serialise to text (or bytes); a dict doesn't. The fixed version (on disk now) wraps the dict in json.dumps(...) to return a string. Resources return text; serialise structured data with json.dumps() first.

§ 04 — THREE PRIMITIVES

Tool vs Resource vs Prompt, with FastMCP

The three primitives look almost identical in code. The distinction is who initiates the call.

PrimitiveDecoratorIdentifierWho triggers itUse for
Tool@mcp.toolfunction nameLLM picks during reasoningActions: query DB, send email, run a calculation
Resource@mcp.resource("uri")URIApplication/host attaches to contextRead-only data: docs, configs, file contents
Prompt@mcp.promptfunction nameUser picks via slash commandTemplated requests the user invokes
Correction — "resource is not auto-discoverable" is the lecturer's shortcut, not the protocol's design.

The protocol lets clients list_resources() exactly like list_tools(). The difference isn't discoverability — it's that resources are typically chosen by the host UI, while tools are chosen by the LLM mid-reasoning. Same wire format; different control flow above.

Correction — prompts and resources aren't deprecated.

The lecturer says resources are "outdated" and prompts are "replaced by other tools." Neither is true. Resources are how Claude Desktop attaches documents via @-mention. Prompts are how Cursor and Claude Desktop expose slash commands. Heavily used. Treating MCP as tools-only is the lecturer's stylistic preference, not the protocol's intended use.

JAVA/SPRING BRIDGE

@mcp.tool ≈ @PostMapping on a REST controller. Same pattern: a decorator/annotation that says "this function is callable from outside; here's its signature." The framework generates the schema, handles dispatch, and serialises results. @mcp.resource is closer to @GetMapping (read-only data at a URI).

§ 05 — CLIENT

Anatomy of an MCP client

The client side (simple_client.py) is just as small:

"""
Beginner MCP Client - Tests Tool, Resource, and Prompt
"""
import asyncio
import os

from fastmcp import Client

# Subprocess stdio (default) or HTTP URL if MCP_HTTP_URL is set
SERVER = os.environ.get("MCP_HTTP_URL", "simple_server.py")


async def main():
    async with Client(SERVER) as client:                # ← opens the connection
        # ---- 1. TOOLS ----
        tools = await client.list_tools()               # ← discover what's available
        result = await client.call_tool("add", {"a": 5, "b": 3})
        print(f"add(5, 3) = {result.content[0].text}")

        # ---- 2. RESOURCES ----
        resources = await client.list_resources()
        r1 = await client.read_resource("resource://greeting")
        text = r1[0].text if hasattr(r1[0], "text") else str(r1[0])
        print(f"resource://greeting = {text}")

        # ---- 3. PROMPTS ----
        prompts = await client.list_prompts()
        prompt_result = await client.get_prompt("explain_topic", {"topic": "MCP"})
        msg = prompt_result.messages[0].content
        text = getattr(msg, "text", str(msg))
        print(f"explain_topic('MCP') = {text}")


if __name__ == "__main__":
    asyncio.run(main())

Why async

Every FastMCP client call is async. asyncio gives you cooperative concurrency, not parallel execution. The point: while the client is waiting on the server to respond to one request, the program can do other work.

CONCURRENT ≠ PARALLEL

The lecturer was right on this distinction. Parallel is two threads or two processes running simultaneously on different CPU cores. Async/concurrent is one thread that interleaves multiple in-progress operations by yielding at I/O boundaries. Python's asyncio does the latter, not the former — to get real parallelism in CPython you need multiprocessing or release the GIL.

§ 06 — RUNNING

Running it

Option A — stdio (client spawns server)

The default. Open one terminal, run the client; it spawns the server as a subprocess automatically:

python simple_client.py

Option B — HTTP (server is a long-running service)

Use this when the server has expensive startup, runs on a different host, or should serve many clients. Two terminals:

# Terminal 1 — start the HTTP server
python simple_server.py --http
# → Uvicorn running on http://127.0.0.1:8001

# Terminal 2 — point the client at the HTTP URL
export MCP_HTTP_URL=http://127.0.0.1:8001/mcp
python simple_client.py

The client code is identical; only the SERVER variable changes. That's the point of MCP — same protocol, two transports.

§ 07 — WRAPPING

Wrapping third-party APIs as your own MCP tools

The flight-tracking example the lecturer attempted: a tool that queries OpenSky Network for live aircraft positions over a named region.

import urllib.request, urllib.parse, json
from fastmcp import FastMCP

mcp = FastMCP(name="Flight Tracker")

REGIONS = {
    "new york": (40.0, -75.0, 42.0, -72.0),
    "london":   (51.0,  -1.0, 52.0,   1.0),
    "tokyo":    (35.0, 139.0, 36.0, 140.0),
}

@mcp.tool
def search_flights_in_region(region: str) -> str:
    """Return live aircraft currently flying over the named region.

    Args:
        region: One of 'new york', 'london', 'tokyo'.
    """
    key = region.lower().strip()
    if key not in REGIONS:
        return json.dumps({"error": f"Unknown region: {region}"})

    lamin, lomin, lamax, lomax = REGIONS[key]
    params = urllib.parse.urlencode({
        "lamin": lamin, "lomin": lomin, "lamax": lamax, "lomax": lomax,
    })
    url = f"https://opensky-network.org/api/states/all?{params}"
    with urllib.request.urlopen(url) as resp:
        data = json.loads(resp.read())
    return json.dumps({
        "region": region,
        "count": len(data.get("states") or []),
        "states": data.get("states", [])[:10],
    })


if __name__ == "__main__":
    mcp.run()
Correction — the lecturer's framing was slightly off here.

She described this as "calling the OpenSky MCP server." Strictly: this is a Python function that calls OpenSky's REST API (an HTTPS endpoint, not an MCP server) and wraps the response. You — the server author — are doing the protocol translation. The "I'm calling an MCP server" framing applies to genuine MCP-native servers. Everything else is you wrapping an existing API as an MCP tool, which is the most common pattern.

§ 08 — RECIPE

How to learn a third-party MCP server (so you can wrap it)

When you want to expose a third-party service as one of your tools, the recipe is:

  1. Find the service's docs. GitHub readme, OpenAPI spec, vendor docs.
  2. Identify the operations you need. Probably 3-10 of the service's endpoints, not all of them.
  3. For each operation, note input parameters, return shape, and auth requirements.
  4. Write one @mcp.tool per operation in your own server.
  5. Test with simple_client.py-style code first. Get the wire-level tool call working before adding it to Cursor.

The lecturer's slogan: "You don't have to teach the LLM to write Cypher queries. Wrap Neo4j's query API as one tool, document it, done. The LLM writes Cypher; your tool runs it; the result comes back; the LLM reads it; the user gets an answer in English."

This is the whole point of MCP for domain-specific work. Each tool is an "I'll handle the boring API plumbing; you handle the reasoning" contract between you and the LLM.

§ 09 — SECURITY

Security, briefly

The lecturer's enterprise reality: most third-party MCP servers are blocked. Your own MCP server, hosted internally, is the only path. A few points:

  • MCP servers run with full local user privileges (file system, network, env vars). Treat each server like an installed program.
  • stdio transport is the least-bad default — server is a subprocess in your IDE's process tree, no network surface.
  • HTTP transport introduces a network surface. If you expose it on the LAN, secure it: token auth, network policy, etc.
  • Tool inputs are LLM-generated. If your tool runs SQL, the LLM might generate a SQL injection. Validate inputs at the tool boundary (parameterised queries, allowlists, schemas).
  • The OWASP LLM Top 10 (2025 edition) specifically calls out Excessive Agency and Insecure Plugin Design. Both apply to MCP servers.

An MCP server with a delete_file(path: str) tool is, from the LLM's perspective, a function it can call. The LLM may call it. Decide whether that's OK before you expose it.

Glossary

async with
Python's context manager for asynchronous resources.
await
Yields control to the event loop until the awaited operation completes.
Cooperative concurrency
One thread, many in-progress operations, control yielded at I/O boundaries. Python's asyncio model.
FastMCP
The de facto Python framework for writing MCP servers and clients. jlowin/fastmcp; now vendored as part of the official Anthropic Python SDK.
HTTP transport (streamable HTTP)
One of MCP's two transports. Server is a long-running HTTP service.
json.dumps
Serialises a Python object to a JSON string. Required for returning structured data from @mcp.resource.
@mcp.prompt
FastMCP decorator that registers a function as a prompt template. User-controlled.
@mcp.resource(uri)
FastMCP decorator that registers a function as a resource at a given URI. Application-controlled.
@mcp.tool
FastMCP decorator that registers a function as a tool. Model-controlled.
OpenSky Network
A free, public service that aggregates ADS-B aircraft position data. Not an MCP server; a REST API you can wrap as one.
stdio transport
One of MCP's two transports. Server is a subprocess; communication via stdin/stdout pipes.
uvicorn
The ASGI server FastMCP uses to serve HTTP.
