The TransformerEncoder

How text becomes context-aware numbers — the architecture that broke open modern AI.

2017 PAPER "ATTENTION IS ALL YOU NEED"
Every token in the input is enriched with three layers of information — what it means generically, where it sits, and how it relates to every other token. Once each token carries all the context it needs, the model can process them in parallel.
Scope note. Everything below describes inference — running a trained model on your prompt — unless otherwise marked. Training shares the machinery but answers a different question (adjust the weights so future predictions are better).
§ 01 — STARTING POINT

Why text becomes numbers

Models consume numbers, not characters. Text is unstructured, so every input must be turned into a numeric form before anything else can happen. ChatGPT (application) wraps GPT (model), which is a Transformer implemented in a DL framework like PyTorch.

The user-visible task — "answer my prompt" — is, at inference time, predict the next token, then the next, then the next. Each step is a probability distribution over the vocabulary; the model samples from it. So output is not deterministic and not a database lookup; it's repeated probabilistic prediction.

This is also why hallucination is the default mode of an LLM, not a bug of specific models — it's sampling plausible continuations, with no ground-truth check.

Inside one prediction step, all the input tokens are processed in parallel rather than one-after-another. That's the encoder's job in this session.

JAVA / SPRING BRIDGE

Think of an embedding lookup as a Map<Token, float[]> against a pre-trained dictionary — a deterministic translation step before the "real" service logic runs. The dictionary ships with the model.

§ 02 — GENERIC EMBEDDINGS

Words as coordinates in latent space

Take a vocabulary (~20,000 root forms is the lecturer's example — modern LLMs use sub-word tokenizers with 32k–250k tokens; see §11). Each token gets mapped to a vector of fixed dimensionality — 256, 512, etc. — chosen by the architect.

The lecturer's animal / bird / sky / machine axes are a teaching metaphor. Real Word2Vec dimensions are not human-interpretable topics — they're latent dimensions learned from data. Words with similar usage end up close together in the vector space, but the individual axes don't carry labels you'd recognize. Useful for intuition; just don't expect to open up a real embedding and find "axis 47 = bird-ness."

Correction. The lecturer said "scores along the axes should sum to 1." That's not true for Word2Vec — components are real-valued, can be negative, and are not normalized. The "sums to 1" rule applies later, to attention weights (rows of the attention matrix are softmax-normalized) — not to the word vectors themselves.
THE KEY LIMITATION

These embeddings are generic. The vector for dog is identical in "man bites dog" and "dog bites man". Word2Vec carries no order and no input-specific context.

§ 03 — PROBLEM 1: ORDER

Positional encoding

"Man bites dog" and "dog bites man" share the same three words and therefore the same Word2Vec vectors, but they mean opposite things. English meaning depends heavily on position.

The fix: add a positional encoding to each token's generic embedding. Conceptually, attach a position index (0, 1, 2, …) so the two sentences yield different combined embeddings even though the words are identical. The actual 2017 scheme uses sine/cosine functions of position — that's Session 8's math.

Why add (not concatenate)? To keep dimensionality constant through the stack. Concatenation would grow the vector at every layer and blow up compute. Adding stays at d_model (512 in the original paper).

§ 04 — PROBLEM 2: RELATIONSHIPS

Attention — what looks at what

Position alone still doesn't cover "Ram is going to school. He is a good student." The model needs to know he refers to Ram. That's a relationship between tokens, not a property of either token in isolation.

The fix: for every token, attach a relationship vector — scores for how strongly that token relates to every other token in the input (including itself). The scores come from a softmax, so each row sums to 1. For "man bites dog", the row for man might be (man:0.5, bites:0.4, dog:0.1) — illustrative, not real numbers.

This is the attention score. Unlike Word2Vec it is input-specific (contextual): the same word in two different sentences gets two different attention rows. This is the 2017 innovation.

HONEST DISANALOGY — NOT A JOIN

Self-attention is not a database JOIN. A JOIN matches on equality (a.id = b.id). Attention computes a learned soft similarity between every pair of tokens via Q/K/V projections (Session 8). The closest Spring-world analog is a custom matcher that scores all pairs and produces weighted aggregates — even that misses the point.

§ 05 — THE SYNTHESIS

The three-layer embedding

For each token, the encoder produces a single vector that bundles three layers, summed together:

generic + positional + attention-mixed = rich embedding
LAYER 1
Generic embedding
English-level meaning (Word2Vec-style). Same in every sentence the word appears in. Real-valued, not normalized.
LAYER 2
Positional encoding
Where the token sits in the input. Added once, before the encoder stack. Position doesn't change between layers.
LAYER 3
Attention-mixed representation
A weighted blend of all tokens' representations, where the weights are this token's attention scores (softmax-normalized, sum to 1). Recomputed at every encoder layer.

These are added, not concatenated — context is enriched without growing the dimensionality. Once every token carries its position and its mixed-in view of all the others, no token has to wait for any other token's processing. That's what unlocks parallel execution.

§ 06 — THE STRUCTURAL BREAK

Sequential vs parallel

BEFORE 2017 — RNN / LSTM

One token at a time

  • ⚠ Vanishing gradients on long input
  • ⚠ Strictly serial — hard to use a GPU
  • ⚠ Long-range dependencies decay
2017+ — TRANSFORMER

All tokens at once

  • ✓ Every token attends to every other
  • ✓ Massively parallel on GPU
  • ⚠ But: O(n²) compute in length

Two things to keep honest about Transformers:

"All at once" isn't free. Attention is O(n²) in sequence length — doubling the input quadruples the attention compute. The structural win over RNNs isn't constant-time processing; it's that the work is massively parallel on a GPU instead of an inherently serial loop.

Long-context isn't solved, just better. Context windows have grown from 2k → 200k → 1M+ tokens, but quality degrades over very long contexts and cost scales accordingly. The long-range-dependency problem is mitigated, not eliminated.

§ 07 — ARCHITECTURE

The encoder block

One encoder block, in order:

INPUT
tokenize
EMBED
lookup
POSITION
add (once)
ATTENTION
self-attention
FFN
feed-forward

Steps 4 and 5 each have a residual connection and a layer normalization wrapping them — the paper writes this as LayerNorm(x + Sublayer(x)). The lecturer's "add" arrow is this residual; it's important for training stability and lets gradients flow through deep stacks.

The original paper stacks the block 6 times. From block 2 onward, the input is the previous block's output, not the raw embedding — each layer refines the representation further. Positional encoding is not re-applied inside the stack; only attention + FFN repeats.

The number 6 isn't sacred — production LLMs use far more (BERT-base = 12, BERT-large = 24, GPT-3 = 96 decoder layers). What matters is that the pattern repeats.

JAVA / SPRING BRIDGE

Each encoder block is like a Spring Filter in a FilterChain — it takes the request, transforms it, and passes the (now-richer) request to the next filter. Stacking filters compounds the transformation; the same request object flows through with progressively more information attached.

§ 08 — WHY DEPTH HELPS

Why repetition works

Repetition is not a Transformer-specific trick — it's how deep models capture progressively more abstract patterns.

ANN stacks hidden layers (1, 3, 5, 10…) for the same reason. CNN stacks convolution blocks; early layers catch edges, deeper layers catch parts, deepest layers catch whole objects.

Each Transformer block sees richer input than the last, so stacking lets the model learn finer-grained patterns in the text.

REMEMBER

AI ≈ pattern recognition.

Depth gives you more patterns. (Useful slogan, not a precise definition.)

§ 09 — TWO HALVES

Encoder vs decoder

ENCODER

Represents

Takes text, outputs enriched embeddings. Not generative. Used in BERT, RoBERTa and most embedding models.

DECODER

Generates

Generates the next token. Runs autoregressively — predict one token, append it to the input, predict the next, repeat. Adds masked self-attention (each token only sees earlier tokens). In encoder–decoder models, also adds cross-attention over encoder outputs. Decoder-only models (GPT, Llama) drop the cross-attention.

Different families pick different subsets:

  • Encoder-only (BERT) — understanding tasks: classification, NER, retrieval embeddings.
  • Decoder-only (GPT, Llama) — generation. The prompt is just prepended to the decoder's own context.
  • Encoder–decoder (original Transformer, BART, T5) — translation, summarization — tasks where input and output are clearly distinct sequences.

Picking the wrong family is a real engineering mistake. Using GPT for "extract all the nouns from this paragraph" wastes compute on a generation model when an encoder model would be cheaper and often more accurate.

§ 10 — ASIDES

Worth keeping in mind

Temperature (and what it isn't)

A sampling knob on the decoder. Mechanically, the model produces a vector of logits (unnormalized scores) for each next-token candidate. Temperature scales them before the softmax: logits / T.

Low T (e.g. 0.2) → distribution sharpens, the top token dominates, output near-deterministic. High T (e.g. 1.5) → distribution flattens, lower-probability tokens get a real chance.

Correction. Temperature is separate from top-k and top-p (nucleus) sampling — those truncate the candidate set before sampling. Earlier notes conflated these; they shouldn't be.

Why your GPT ≠ OpenAI's GPT

The algorithm has been public since 2017. The gap is data + compute + post-training:

  • Trillions of tokens of curated training data.
  • Massive GPU clusters (weeks to months of compute).
  • Post-training: supervised fine-tuning + RLHF (Reinforcement Learning from Human Feedback) or related methods. Paid human labelers ranking model outputs.
  • Safety tuning, eval pipelines, serving infrastructure.

Algorithm is commodity; data and the post-training stack are the moat. (Hence the data-center investment frenzy and the strategic value of any pipeline that produces labeled data.)

Hugging Face

Hundreds of thousands of community-built models exist; building your own small Transformer from scratch with PyTorch is a good learning exercise. Don't expect production quality — the limit is data and compute, not the algorithm.

§ 11 — LOOSE ENDS

Worth flagging

Token vs word

The lecturer used "word" and "token" interchangeably. They're not. Modern LLMs use sub-word tokenizers (BPE, WordPiece, SentencePiece). A single English word can be 1, 2, or more tokens — e.g., unbelievable might split into un + belie + vable. Production vocabularies are typically 32k–250k sub-word tokens, not 20k root words. The 20k figure is fine as a rough mental model; just don't think of tokens as English words.

REFERENCE

Glossary

Token
Unit the model processes; sub-word in modern LLMs, not necessarily a whole word.
Embedding
Vector representation of a token.
Word2Vec
Early algorithm producing generic, context-free word vectors via a shallow neural network. Real-valued; not normalized.
Positional encoding
Vector added to a token's embedding to encode its location in the input.
Self-attention
Mechanism producing per-token, relationship-weighted representations across the input. Rows of the attention matrix sum to 1.
Masked self-attention
Decoder variant that hides future tokens during attention.
Cross-attention
Decoder sublayer attending to encoder outputs — present only in encoder–decoder models.
Feed-forward (FFN)
Small per-token neural network (multi-layer perceptron / MLP) sublayer after attention in each block.
Encoder / Decoder
The two halves of the original Transformer; encoder represents, decoder generates.
Logits
Unnormalized scores the model produces before softmax converts them to probabilities.
Temperature
Scaling factor applied to logits to sharpen or flatten the sampling distribution. Distinct from top-k / top-p.
LLM
Large language model — Transformer-based model trained on huge text corpora.
Hallucination
Fluent-sounding output that isn't factually grounded. Default behavior of a probabilistic next-token predictor, not a fixable defect of specific models.
Inference vs training
Inference = running a trained model on your prompt. Training = adjusting the model's weights from data. These notes describe inference unless flagged.
